# コミュニティ機能設計（v0 ドラフト）

作成日: 2026-05-16
位置づけ: MVPでまず作るコミュニティ機能の具体仕様。富澤さんがCursorで実装する際の元ネタ。

> このドキュメントは **暫定** です。`docs/gravity-research.md` のリサーチ結果が出たら、グラビティの優れた部分を取り込んで上書きする予定。

## 設計の原則

1. **能動的な「記録するぞ」を要求しない** — 投稿が記録になる
2. **匿名性は強く担保する** — ハンドルネーム＋アバター。実名・連絡先は出さない
3. **無反応をつくらない** — 通知・自動フォロー・Bot・医療者常駐の組み合わせ
4. **病気の話をしなくてよい** — 「今日あったこと」程度のつぶやきOK
5. **眺めるだけでもOK** — 受動的参加を肯定（足跡などのプレッシャーを与えない）

## 画面構成（最小）

### 1. オンボーディング（初回起動）

- ステップ1：疾患選択（必須・複数可）
  - UC / クローン / IBD（疾患未確定）/ POEMS / 1型糖尿病 / RA / SLE / その他
- ステップ2：プロフィール（任意・スキップ可）
  - 年代 / 性別 / 都道府県 / 診断時期
- ステップ3：ハンドルネーム＋アバター選択（プリセット8〜12個から選ぶ）
- ステップ4：**最初のつぶやき**（1つだけ書いてもらう・スキップ不可）
  - 例「はじめまして。よろしくお願いします」「最近◯◯がつらい」など
  - 投稿すると即座にBotor運営アカウントがリアクション

### 2. タイムライン（ホーム）

- 上部：自分のルーム切替タブ（疾患別・全体・患者会専用）
- 中央：投稿カードのリスト
  - アバター + ハンドル + 経過時間
  - テキスト（最大300字想定）
  - 画像1枚（任意）
  - リアクション：スタンプ系3〜5種（共感・がんばってる・きいたよ・大丈夫？・ありがとう）
  - コメント数表示・タップで詳細
- 下部：投稿ボタン（FAB常駐）

### 3. 投稿作成

- テキスト入力欄
- 画像添付（カメラ起動 or ライブラリ）
- 公開先：自分が所属するルーム / 全体 / 患者会専用ルーム（所属していれば）
- 匿名度切替：完全匿名 / プロフィール公開（既定は完全匿名）
- **下書きの自動保存**

### 4. ルーム

- 疾患別ルーム（UC / クローン / etc.）
- 属性別ルーム（20代 / 30代 / 子育て中 / 仕事と治療の両立 など）
- 患者会専用ルーム（招待コード or 患者会管理者が承認）
- ルーム内タイムラインは「全体」より優先表示

### 5. 通知

- 自分の投稿への反応・コメント
- 自分がフォローしてる人の新規投稿
- 同じルームに新しい人が来た（オンボ後の最初の投稿が流れる）
- 医師・薬剤師アカウントからのコメント（特別アイコン）

### 6. プロフィール

- 自分の投稿履歴
- 自分のリアクション履歴
- フォロー / フォロワー
- 設定（通知・公開設定・アカウント削除・データエクスポート）

## 「優しさ」を担保する仕組み

### モデレーション

- 投稿は **AI事前チェック**（差別・誹謗中傷・医療デマ・自殺示唆）
- 引っかかった投稿は **公開前** に運営に回す（ユーザーには「確認中」表示）
- 通報ボタンを各投稿・コメントに常駐
- ブロック・ミュート機能

### 自殺示唆・緊急ワード検知

- 「死にたい」「消えたい」等の検知時：
  - 投稿は普通に公開
  - **ただし投稿者に** いのちの電話・よりそいホットライン等の連絡先カードを通知でそっと表示
  - 急性期の介入はしない（押し付けない・指示しない）

### 「無反応」を作らない

- 初回投稿 → 必ず運営Bot or 医療者アカウントが30分以内に1リアクション
- 6時間反応ゼロの投稿 → 運営アカウントから「読んでくれている人がいるよ」スタンプを自動付与
- 同じ疾患ルームの先輩患者を「最初のフォロー候補」として自動提示

### 桜的設計（合意の上で）

- 初期はメディキャンバス側スタッフが匿名アカウントで参加
- ガイドライン：絶対に嘘をつかない、医療判断をしない、共感ベース
- ユーザーが増えてきたら段階的にフェードアウト

## 記録への自動連携（v1.5以降）

投稿のテキストから自動抽出してプロフィールに紐づける：

| 投稿例 | 抽出される記録 |
|---|---|
| 「今日からレミケード3クール目」 | 薬剤：レミケード、イベント：3回目投与 |
| 「お腹が痛い、トイレ5回」 | 症状：腹痛、IBD関連：排便回数 |
| 「主治医に手術の話された」 | イベント：診察、トピック：手術検討 |
| 「副作用で吐き気が出てる」 | 副作用記録 |

→ プロフィール画面で時系列に表示。間違ってたら手で修正。

## 医師・薬剤師アカウントの扱い

- 専用バッジ（青✓的なもの・別カラー）
- プロフィールに「資格・所属」表示
- コメント時は **必ず免責文** が自動付与：
  > このコメントは一般情報の共有であり、個別の診断・治療方針ではありません。主治医にご相談ください。
- 「相談」ボタンは作らない（責任関係が重くなりすぎる）

## 患者会連携の機能

- 患者会管理者向け管理画面：
  - 会員招待URL発行
  - 専用ルーム作成・モデレーション
  - イベント告知投稿（リアル患者会のオフ会など）
  - 会員数・投稿数のダッシュボード
- 会員には「患者会員バッジ」表示
- 患者会同士は独立（混ざらない）

## データモデル（雛形）

```
users:
  id, handleName, avatar, createdAt
  privateProfile: { realName?, age, gender, region, diseases[], onsetDate }
  publicProfile: { handleName, avatar, badges[], diseaseTagsOptional[] }

posts:
  id, userId, roomId, text, imageUrl?, visibility(public/room/patientGroup)
  reactions: { kind: count }
  createdAt, isAnonymous

comments:
  id, postId, userId, text, createdAt, isModerator?

rooms:
  id, type(disease/attribute/patientGroup), name, description, memberCount
  moderators[], rules

reactions:
  postId, userId, kind, createdAt

extractedRecords:  ← v1.5〜
  id, userId, sourcePostId, kind(medication/symptom/event/sideEffect), value, confidence

patientGroups:
  id, name, contactPerson, roomId, memberInviteCode
```

## 技術スタック候補（要決定・5/16 MTGで議論）

| レイヤ | 候補A（既存PHR踏襲） | 候補B（モダン寄り） |
|---|---|---|
| フロント | Vanilla JS + LIFF | React Native + Expo / Flutter |
| サーバ | Node + Express | 同左 / Hono / Bun |
| DB | Firestore | Firestore / Supabase |
| 認証 | LINE LIFF | LINE + 独自 / メールマジックリンク |
| 配信 | Cloud Run | Cloud Run / Vercel |

**推奨**: 富澤さんがCursorで作るので、富澤さんが最速で動かせるスタックを選ぶのが正解。
たぶんReact + 軽量バックエンドが妥当。LIFFに縛られない方が、ストアアプリ化の余地が残る。
