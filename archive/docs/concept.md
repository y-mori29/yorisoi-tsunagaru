# コンセプト

作成日: 2026-05-16
更新元: 2026-05-15(木) 21:30〜22:25 ブレストMTG（冨澤・添田・森）

## 一行で

> グラビティのような優しいSNSで、同じ病気を抱える人とゆるくつながりながら、診察記録・薬・体調が「気づけば残っている」状態をつくる。

## なぜ別プロダクトとして立てるのか

既存の `yorisoi-phr` は「医療パスポート（医師×患者の記録）」「タイムライン中心」「毎日使うアプリではない」という設計判断のもと作られている。
今回ブレストで浮かび上がった軸は、**真逆**に近い：

- **続けたい**と思える / **毎日のように**触れたくなる
- **病気の話だけじゃない**、つぶやきレベルの軽い関わりOK
- **デザイン・キャラクター・温度感**で安心感を生む
- 記録は「ついで」「副産物」として自然に貯まる

既存PHRに「コミュニティ機能を後付け」しても、思想がぶつかって両方とも中途半端になる。
だから **ゼロから別プロダクト** として立ち上げる。

## 2軸の核

### 1. コミュニティ（前面・体験の中心）

- イメージは **GRAVITY（グラビティ）** — 匿名で、優しく、攻撃のない「やさしいSNS」
- 病気の話を必ずしも投稿しなくてよい。「今日あったこと」レベルでつながれる
- ルーム＝疾患/属性ごとの集まり（例：UC / クローン / POEMS / IBD全般 / 30代 / 子育て中 など）
- 「他の人の体験を眺める」だけでもOK（受動的参加を肯定する）

### 2. 記録（背景でビジネスを支える）

- 製薬企業向け：**リアルな患者体験 × 診察会話 × 薬の服用状況** が紐づいたデータが価値
- 患者向け：**重い病気の人ほど** 「前回何を話したか」「主治医に何を伝えるか」の整理に価値
- ただし **記録ボタンを能動的に押させる設計ではない**：コミュニティの投稿が自然に記録に流れる導線を作る

## 「どっちかに寄せない」判断

ブレスト中の重要な分岐：

> **A案：たくさんの機能を1つに統合する（食事も薬もトイレも全部入り）**
> **B案：1つの機能（記録）に特化して、他は連携で済ます**

→ 結論は **B寄り、ただし「特化させたい機能」は「コミュニティ」**。

理由：

- 機能を山盛りにすると「面倒そう」で初手離脱する（前回インタビューの裏付け）
- 他社の単機能アプリ（食事記録・トイレマップ・お薬手帳）は既に成熟しており、勝ち目が薄い
- コミュニティで **新しい価値** を作り、そこから記録へ自然に流す方が、新規参入で勝ち筋がある

## 課金 / ビジネスモデル（背景）

- ユーザーは **無料**（あるいは極めて軽い課金）
- 収益源は **製薬企業へのデータ提供 / インサイト提供**：
  - 患者プロフィール（属性・薬剤歴・副作用歴）
  - リアルタイム情報（診察会話の要約・症状トレンド・統計処理されたデータ）
  - 過去情報（体験談・治療歴）
- 既存の置換手段は **MRが医師に聞く + 患者インタビュー**：時間がかかり、患者の声の真正性も担保しにくい
- このアプリはその「ブラックボックス」を埋める一次データソースになる

## ターゲット患者像

ブレストの中で、添田さんから出てきた疾患重症度の整理：

| タイプ | 例 | 主要価値 |
|---|---|---|
| 安定期 / 慢性 | UC寛解期、コントロール良好な糖尿病 | **コミュニティ**（つながり・共感・継続のドライバー） |
| 進行性 / 重め | 進行性白血病、POEMS、難病急性期 | **記録**（前回会話・手術前説明・症状経過の整理） |

→ どちらかだけでは欠けるので、**両方持つアプリ** にする必要がある。

## 患者会との連携

- 既に乗り気な患者会がある（座骨章 ※聞き起こし誤変換の可能性、大阪IBD など）
- 患者会の側にも「アプリを作って患者を呼び寄せたい」というニーズがある
- → このプロダクトを**患者会の入り口**として提供できると、Win-Win
  - 患者会側：アプリ作成コスト不要、会員獲得導線になる
  - 我々：患者会経由でユーザー獲得＋データソース化

## 医師・薬剤師の関与（差別化点）

- 河野田先生・水野先生らに「監修者」「相談コメント返し」として関わってもらう案
- 添田さん本人も薬剤師
- **「本物が作っている」「専門家がいる」** ことが他のSNSとの決定的な差別化になる

## 初期ユーザー導入の壁と対策

- SNSは「最初の1人」「最初の投稿」「最初の反応」が死ぬほど難しい
- 対策：
  - 初回インストール時に **必ずワンアクション** させる（自己紹介投稿1回など）
  - 投稿があると **既存ユーザーに通知** が飛ぶ
  - 一定数集まったら **自動フォロー** 候補を提示
  - 初期は **運営側がBot・桜的な存在** で気持ちよくする設計（森さん発案）
  - **医師・薬剤師の常駐コメント** で「無反応の不安」を消す

## 何を作らないか（明示）

- 食事記録専門アプリ（あすけん的）→ **作らない**。連携にもしない。
- トイレマップ専門機能 → 既存PHR側に温存（連携することはあり得る）
- お薬手帳 → 連携するが本体機能には組み込まない
- 重い病気の自己診断・重症度判定 → AIにやらせない（既存PHR時代からの原則継承）
