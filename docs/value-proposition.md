# 価値の言語化（5/16 MTG持参資料）

作成日: 2026-05-16 09:30 — 当日10時の冨澤さんMTG向け

## このドキュメントの目的

冨澤さんから前夜に「価値の部分をちゃんと言語化して持ってくる」と宿題を受けた。
ここで言語化するのは **「誰の・何の課題を・どう解決し・なぜ我々のプロダクトでなければならないか」**。

明日のMTGはこのドキュメントを叩き台にして、コミュニティ機能の方向性を確定させる。

---

## 1. 誰のための価値か（3層構造）

このプロダクトの価値は3者に対して同時に発生する。

### A. 患者本人（無料ユーザー）

- 同じ病気の人と **匿名で** ゆるくつながれる
- 弱音を吐ける、聞いてもらえる、誰かが反応してくれる
- 「他の人もそうなんだ」という安心感
- 病気の話以外もしていい（負荷の低い継続）
- 副次的に、診察会話の要約や薬の記録が「気づけば貯まっている」

### B. 患者会（一次集客導線）

- 自前でアプリを作る予算・人手はないが、会員に提供したい体験はある
- このアプリを「患者会の入り口」として無償提供
- 会員獲得導線になる／既会員のリテンションが上がる
- 患者会から「うちの患者さん専用ルーム」が作れる

### C. 製薬企業（収益化先）

- 患者の **リアルタイム情報** が欲しい（特に診察会話の中身・副作用の生の声）
- 既存はMRヒアリング＋患者インタビュー＝時間とコストがかかる上、真正性が怪しい
- 我々：継続的に取れる **真正な一次データ** を提供できる（個人特定を排した形で）

## 2. 患者本人の課題（前回・今回のインタビューから）

### 課題1：孤独・不安を吐き出す場所がない

- IBD患者は **LINEを交換して** 患者同士でつながっている（ブレスト中の発言）
- → 既にニーズがあるが、LINEは個人情報が漏れすぎる／関係が深くなりすぎる
- 求められているのは「**もっと薄い、軽い、ゆるい関係**」（冨澤発言）

### 課題2：「記録しろ」と言われるが面倒

- 血圧・SpO₂・食事・症状・薬を毎日記録するよう医師に言われる
- 本人もひどくしたくないから記録する **が、記録自体がめんどくさい**
- 重症化したタイミングでは「それやるのか」となる
- → **「記録のための記録」をやめさせる** ことが鍵

### 課題3：診察の内容を忘れる／伝えきれない

- 前回診察で何を話したか、自分も家族も忘れている
- 自分の状況を5分で要約して伝えるのが難しい
- 客観的にサクッと伝えられたら、診察の質が上がる

### 課題4：情報がアプリごとに散らばっている

- 食事記録は食事アプリ、お薬は別アプリ、トイレは別アプリ
- 「全部入り」を作ると逆に面倒で離脱する（前回インタビュー）
- → **1つに統合するのではなく、1つに特化して、新しい価値を作る**

---

## 3. 我々の解：コミュニティ × 記録（ハイブリッド）

### 解の核

| 課題 | 解 |
|---|---|
| 孤独・吐き出し場所がない | グラビティ風の優しいコミュニティ（疾患特化ルーム） |
| 記録が面倒 | コミュニティ投稿が **そのまま記録** になる導線（つぶやき→症状・薬の自動タグ付け） |
| 診察内容を忘れる | 音声記録→AI要約→主治医ノート化（既存PHRの強み移植） |
| アプリが散らばる | 「コミュニティ」「記録」の2機能だけに絞る（他は連携しない／別アプリで） |

### コミュニティ → 記録 への接続例

ブレスト中に添田さんが言ったポイント：

> 自分のつぶやきで「今日この薬を使ってる」とあれば、それはそれで薬の情報に紐付くし、
> 「今日は体調が悪いな」という投稿だったら、患者の調子が下がっているという状況になる。
> そういう **会話記録** が取れてさえいれば、別途記録ボタンを何度も押させる必要はない。

→ **「つぶやき」が「記録」の正体** という設計思想。

## 4. なぜ我々のプロダクトでなければならないか（差別化）

### 差別化軸1：医師・薬剤師の常駐

- 河野田先生・水野先生・添田さん（薬剤師）らが **本物の医療者として** コメント・監修
- 他のSNSにはない「**専門家がそばにいる**」体験
- 「本物が作っている」というメッセージ

### 差別化軸2：疾患特化のルーム設計

- グラビティは裾野が広すぎて、同じ病気・悩みの人が見つけにくい
- 我々は **疾患・属性軸でルームを設計** （UC / クローン / POEMS / 30代女性 / 子育て中 など）
- 患者会との連携で「**会員専用ルーム**」も作れる（座骨章・大阪IBD などとの提携）

### 差別化軸3：記録の自動化

- 「記録専用アプリ」は面倒で続かない
- 「SNS専用アプリ」は記録という付加価値がない
- 我々：**SNS体験の副産物として記録が貯まる** ハイブリッドはこの形では他にない

### 差別化軸4：ビジネスモデルが患者を圧迫しない

- 患者から課金しない（あるいは極小）
- 製薬企業へのインサイト提供で収益
- → 患者は **使い続けるほど社会的に意味のあるデータが貯まる** という建付け
- 個人特定は排する設計（プライバシー第一）

## 5. MVPで作る／作らないの線引き

### 作る（最初の動くもの）

- グラビティ風タイムライン UI（匿名投稿・コメント・スタンプ的なリアクション）
- 疾患選択 → 自分が所属するルーム自動アサイン
- 投稿に対する **「他のユーザー」からの通知**（運営Botでも可）
- 医師・薬剤師アカウント（手動運用OK）
- プロフィール（性別・年代・住んでるエリア・疾患・薬・副作用歴）

### 作らない（v1.0で）

- 食事写真記録機能
- トイレマップ
- お薬手帳のフル機能
- 検査値グラフ（既存PHRがあるので連携扱い）
- 自己診断・重症度判定AI

### 後で作る（v1.5〜）

- 音声記録 → AI要約 → 主治医ノート化（既存PHRから機能移植）
- 製薬企業向けインサイトダッシュボード
- 患者会管理画面（ルームモデレーション）

## 6. 想定される反論と対応

### 反論1：「他のSNS（X・Threads・グラビティ）でいいじゃん」

- → 疾患特化／医師薬剤師の存在／患者会連携 がない
- → 患者会という閉じた信頼コミュニティから入る導線が決定的に違う

### 反論2：「結局コミュニティは死ぬよ」

- → 死なせない設計を初期から：
  - 運営側Botと桜的アカウントで初期反応を作る
  - 医師・薬剤師の常駐コメント
  - 自動フォロー機能で「無反応」を作らない
  - 患者会経由で「すでに知り合い」が一定数いる状態でローンチ

### 反論3：「記録の自動化って結局AIの精度次第でしょ」

- → そうだが、既存PHRで AI要約の精度は実用レベルまで来ている
- → 完璧でなくてよい。「ついで」「副産物」なので、間違ってたら手で直せばよい
- → 重要なのは「**記録するために投稿してる感がない**」体験設計
