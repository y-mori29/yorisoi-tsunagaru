# よりそい つながる 画面・機能整理

作成日: 2026-06-23
対象: `medicanvas/yorisoi-tsunagaru/frontend`
公開URL: `https://tsunagaru-frontend-450637239907.asia-northeast1.run.app`

## 目的

「病気・症状・診断前の不安を、ひとりで抱えないためのやさしいコミュニティ」として、画面と機能を整理する。

水曜デモ、今後の実装、説明資料でぶれないように、現時点の画面を次の6つに分ける。

プロダクトの再整理方針は `community-product-restructure-principles-20260623.md` にまとめる。

病名・症状・不安・部屋を固定リストから解放するための詳細設計は `community-topic-data-design-20260623.md` にまとめる。

1. 登録前に読める入口
2. 病気・症状・悩みから探す
3. 部屋で近い声を読む
4. そっと吐き出す
5. 登録・ログイン後にできること
6. 補助画面・設定画面

## 全体コンセプト

よりそい つながるは、一般的なSNSではなく「体験談を読み、近い声に出会い、書ける時だけ少し置ける場所」として設計する。

- 医療判断をする場所ではない。
- 競争指標や拡散を前面に出さない。
- 登録前でも読める。
- 投稿・反応・保存など、本人の行動が残るものは登録後にする。
- 体験談数を少なく見せる数字表示は避け、流れている投稿量と「もっと読む」で人の気配を出す。
- 投稿者名は分類ラベルではなく、普通のユーザーネームにする。
- 病気・症状・暮らしの悩みは、初期表示だけでなく検索・もっと見るで大量に広げられる前提にする。
- 病名は固定候補だけにせず、検索、候補外の自由入力、診断前の入口、内部テンプレート分離で受け止める。

## 主要導線

### 登録前の人

```text
/home
  → 最新・近い声・病気・症状・悩みのタイムラインを読む
  → /find で病気・症状・悩みを探す
  → /rooms/[id] で近い部屋の声を読む
  → 反応・保存・投稿を押すと /auth/register へ
```

### 登録する人

```text
/auth/register
  → メールアドレス登録
  → Google登録はフロント実装済み、GCP側OAuth設定待ち
  → 登録後 /home または next 指定先へ
```

### 書きたい人

```text
/post
  → 近い気持ちを選ぶ
  → 本文を書く
  → 全体 / 部屋 / 自分だけ を選ぶ
  → /home または /rooms/[id] へ戻る
```

## 機能整理

### 1. 登録前でも読める公開体験

対象画面:

- `/home`
- `/find`
- `/rooms`
- `/rooms/[id]`
- `/voice/[id]`

現在できること:

- 投稿カードを読む
- 病気・症状・悩みのタグから探す
- 部屋一覧を見る
- 部屋詳細の体験談を読む
- 「もっと読む」で投稿が増える

次に強めること:

- 体験談データ由来であることを、信頼を損なわない場所に表示する
- 投稿の生活リズムや時間帯の自然さを増やす
- ペルソナごとの口調・背景が続いているように見せる

### 2. 探す・分類する機能

対象画面:

- `/find`
- `/rooms`
- `/rooms/[id]`

現在できること:

- 病気、症状、暮らしの悩みを検索
- 各カテゴリで「もっと見る」
- タグから部屋またはタイムラインへ進む

次に強めること:

- 病気・症状・悩みマスターを静的JSONとして整理する
- 表記ゆれを持つ。例: `潰瘍性大腸炎` / `UC`、`全身性エリテマトーデス` / `SLE`
- 「診断前」「病名がまだ分からない」人の入口を強くする
- 病名は固定リストだけにせず、検索と自由入力を前提にする
- 患者さんが選んだ/入力した病名と、アプリ側で使うテンプレートを分けて保存する
- 部屋は病名と1対1にせず、病名部屋・症状部屋・不安/暮らし部屋へ案内できるようにする

### 3. 部屋機能

対象画面:

- `/rooms`
- `/rooms/[id]`
- `/post?room=...`

現在できること:

- 病気・症状・悩み別に部屋を読む
- 部屋に入る/出る
- 部屋内で投稿する導線へ進む
- 部屋ごとの書き出しヒントを見る

次に強めること:

- 部屋名を病名・症状・悩みとして自然に整理し続ける
- 部屋ごとの代表投稿、よくある不安、安心ルールを明確にする
- 「入らなくても読める」「入ると保存・反応しやすい」の差を整理する

### 4. 投稿・反応機能

対象画面:

- `/post`
- `/post/condition`
- `/post/star`
- `/home`
- `/rooms/[id]`

現在できること:

- 気持ちチップを選ぶ
- 本文を書く
- 全体、部屋、自分だけを選ぶ
- 投稿後に戻る
- 共感、応援、ありがとう、保存のUIがある

現在の注意:

- 本番DB保存ではなく、デモUIとしての投稿体験。
- 登録前の反応・保存・投稿は登録導線へ進む。

次に強めること:

- 登録後の投稿保存先を決める
- 投稿の公開範囲をDB設計へ落とす
- AIによる「やさしく整える」は、医療判断に見えない制約を入れる

### 5. 登録・ログイン機能

対象画面:

- `/auth/register`
- `/auth/login`
- `/api/auth/firebase-config`

現在できること:

- Firebase設定がある環境ではメールアドレス/パスワード登録・ログイン
- Firebase設定がないローカルではデモ認証へフォールバック
- Cloud Run はFirebase Web App設定済み

未完了:

- GoogleログインのGCP側設定
- Google OAuth Web client ID / secret 作成
- Identity Platform の `google.com` provider 登録

詳細:

- `docs/tsunagaru-google-auth-setup-20260623.md`

### 6. マイページ・通知・設定

対象画面:

- `/me`
- `/me/voices`
- `/notifications`
- `/messages/[id]`
- `/settings/*`

現在できること:

- プロフィールや自分の声を見る
- 通知/会話を見る
- 設定項目を表示する

次に強めること:

- 登録後の本物のユーザー状態と接続する
- 通知とメッセージを本当に使うか、デモでは控えめにするか決める
- 設定画面は多すぎるとデモの焦点が散るため、水曜デモでは見せる範囲を絞る

## 水曜デモで見せる順番

2026-06-24（水）の説明では、次の順が分かりやすい。

1. `/home`
   - 登録前でも、近い声を読める。
   - 人がいて、動いていることを見せる。
2. `/find`
   - 病気・症状・悩みから探せる。
   - 対象がIBD限定ではなく、難病・希少疾患・がん・診断前不安まで広がることを見せる。
3. `/rooms/room-uc` または `/rooms/room-before-diagnosis`
   - 近いテーマの部屋で、同じような声を読める。
4. `/post`
   - 書ける時だけ、ひとこと置ける。
   - 全体、部屋、自分だけを選べる。
5. `/auth/register`
   - 反応・投稿・保存には登録が必要。
   - メール登録は実装済み。GoogleはOAuth設定待ち。

## デモで見せない方がよい画面

水曜デモでは、以下は必要になった時だけ触れる。

- `/settings/*`
- `/showcase`
- `/home-v2`
- `/record`
- `/reflect`
- `/share`
- `/stroll`

理由:

- 今回の価値は「読める、探せる、部屋に入れる、書ける」こと。
- 補助画面を広げすぎると、コミュニティの価値がぼやける。
