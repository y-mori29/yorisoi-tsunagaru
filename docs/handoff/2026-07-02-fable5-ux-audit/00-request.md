# 依頼: よりそい つながる UX監査とそぎ落とし計画

あなたはこのリポジトリ（よりそい つながる＝患者向けコミュニティWebアプリ）のUX監査を担当するAIです。依頼者は森さん（medicanvas創業者・非エンジニア。説明は結論から・初心者でも追える言葉で・日本語）。

## ミッション

UXテスト（回答10件）とミーティング（2026-06-29）で指摘された「分かりにくい・手順が多い・押した後の変化が見えない」を解消するため、**機能追加ではなく、そぎ落としと導線整理**の観点で全画面を監査し、改善計画を作る。

## 進め方（3フェーズ・必ずこの順で）

### Phase 1: 読み込みと現状把握（このフェーズではコードを1行も変更しない）

1. このフォルダの資料をすべて読む: `01-context-and-principles.md` → `10-ux-feedback/`（README→01→02→03→04→05） → `11-source-materials/0629meeting.md`（**ミーティング文字起こしの全文**。要約からでなく原文から読み取ること）
2. リポジトリ本体を読む: `docs/community-product-restructure-principles-20260623.md`、`docs/community-screen-feature-map-20260623.md`、`docs/community-remaining-screen-restructure-plan-20260624.md`、`design-qa.md`、そして `frontend/` の全ルート（`app/**/page.tsx` と共通部品）
3. **読了範囲の申告**: 分析に入る前に、読み込んだファイルと範囲（文字起こしは行範囲、コードはルート一覧）を列挙して報告する。未読のまま全体の結論を出さない。

### Phase 2: 監査結果と改善計画の提示（まだ変更しない）

次の構成で提示する:
- **現状の画面・導線マップ**（実コードから起こしたもの。docsの記述と実装がズレている箇所は明示）
- **指摘事項との突合表**: UXテスト・ミーティングの各指摘 × 該当画面 × 原因の見立て
- **そぎ落とし候補**: 中心機能4つ（読む・ワンタップの声・部屋・記録との接続）に照らして、削る/隠す/後回しにすべき画面・要素・手順のリスト（それぞれ理由つき）
- **改善計画**: 影響度×工数で優先度付けし、2〜4案あるものは比較と推奨を明示
- 判断が必要な箇所は森さんに**1つずつ・選択肢つきで**確認する

### Phase 3: 実装（森さんの承認後のみ）

承認された項目から小さく差分実装する。完了報告は動作確認の証拠つきで、確認済み・未確認・次の一手を分ける。

## 働き方のルール（森さんとの協業原則の要約）

- 迎合しない。指摘を受けたら、前回判断の根拠・不足・変更点を説明する。森さんにない視点・リスクも率直に言う。
- 「できたはず」禁止。未確認のことは未確認と言う。
- 削除は提案のみ（実行は森さんの明示指示後）。ファイルは消さずarchiveへ。
- 医療判断・症状改善・治療助言を約束する文言にしない。価値は「近い声を読む」「記録を残す」「見返す/見せる」。
- UIの水彩・やさしい雰囲気は保つ。ただし見た目のために操作の分かりやすさを犠牲にしない。
