# 要件定義書

作成日: 2026-06-30
対象: よりそい つながる / よりそい 3ボタンLINE

## 1. 背景

UXテスト回答は実質10件。端末は iPhone 4件、Android 5件、その他1件。全員がLINE版を開いて操作できた。

主な定量結果:

| 項目 | 結果 |
|---|---|
| 最初の画面で何をするサービスか分かったか | 平均3.2/5 |
| LINE版の使い方は直感的に分かったか | 平均3.6/5 |
| LINE版を実際の通院で使いたいか | 思う4件 / どちらともいえない5件 / 思わない1件 |

自由記述とミーティングでは、雰囲気への評価は高い一方、操作の意味、手順、表示変化、投稿後の見え方への不安が繰り返し出た。

## 2. プロダクトの位置づけ

### よりそい つながる

登録前でも近い体験談を読み、必要な時だけ声を置けるコミュニティ。SNSの盛り上がりではなく、病気や症状の話を周囲にしづらい人が「自分だけではない」と感じる入口。

### よりそい 3ボタンLINE

診察や体調の話を記録し、あとで本人が見返し、必要な時に医師や家族へ見せるためのLINEアプリ。価値の核は「はなす」で記録を残すこと。

### 2つの接続

3ボタンは、診察や体調変化のタイミングで使う。一方で、記録と記録の間隔が空くと離脱しやすい。つながるは、その間に近い声を読んだり、必要なら短い声を置いたりする場所として機能する。

## 3. 利用者と関係者

| 区分 | 説明 | 主な期待 |
|---|---|---|
| 患者さん本人 | 病気・症状・通院の不安を抱える人 | 迷わず読める、記録できる、必要な時に見せられる |
| 家族・介助者 | 本人の記録や通院準備を支える人 | 代わりに入力・確認しやすい |
| メディキャンバス | 初期検証と改善を進める運営側 | どこで迷うか、どの疾患層に刺さるかを把握したい |
| 開発者/デザイナー | UI/UX改善を進める人 | 何を残し、何を削るかが判断できる |

## 4. 利用シーン

- 初めて「よりそい つながる」を開き、自分に近い病気・症状・悩みの体験談を探す。
- 近い声を読んで、投稿する前に「どこに、どう表示されるか」を確認する。
- 診察後や帰り道にLINE版で録音・メモを残す。
- 次回診察や別の診療科で、過去の記録を見返す/見せる。

## 5. 機能要件

| ID | 要件 | 優先度 | 補足 |
|---|---|---|---|
| FR-01 | つながるの検索・絞り込みは、押した後に何が変わったかを明確に表示する | 高 | 「病気名をクリックしても変化が分からない」対策 |
| FR-02 | タグ・チップ・カードは、押せるものと情報表示だけのものを見分けられるようにする | 高 | 装飾か操作か迷わせない |
| FR-03 | 投稿前に、投稿の公開範囲・表示イメージ・変更可否を確認できる | 高 | 「他人にどう表示されるか不安」対策 |
| FR-04 | 「置く」「吐き出す」など情緒的な言葉は、初回画面では意味が伝わる普通の言葉と併記する | 高 | 例: 「投稿する」「自分だけに保存」 |
| FR-05 | 3ボタンLINEのホームは、初回は「はなす」を主役にし、「ふりかえる」「みせる」は記録後に意味が出る補助導線として見せる | 高 | 並列3ボタンが重いという指摘への対応 |
| FR-06 | 3ボタンLINEの「手入力で残す」導線を、録音の下に隠れすぎない形で出す | 高 | 手入力が分からずつまずいた回答あり |
| FR-07 | 一画面の情報量と入力項目を減らし、まず1操作で進める状態にする | 高 | 「手順が多い」「情報量が多い」対策 |
| FR-08 | 文字サイズと読みやすさを見直し、LINE内ブラウザでも読める基準にする | 中 | Webはピンチアウト可、LINEは難しいという声あり |
| FR-09 | 未実装または押しても反応しない表示を出さない | 高 | `本人の記録` チップなど |
| FR-10 | つながるとLINE版が別サービスに見えないよう、相互導線と説明を整える | 中 | WebサイトとLINEアプリが独立して見えるという声 |
| FR-11 | 次回アンケートでは、疾患名/状況、コミュニティ参加意向、使用場面を分けて聞く | 中 | どの疾患・状況に刺さるかを見る |

## 6. 非機能要件

- 医療判断、症状改善、治療方針の提示を期待させない。
- 個人特定への不安を減らす。病名やハンドルネームの表示設計は慎重に扱う。
- 患者さん本人が受け取る・見返す・見せる体験を主語にする。
- 初期検証では機能数を増やさず、理解しやすさを先に上げる。

## 7. 次回デモ/打ち合わせまでの優先範囲

2026-07-01（水曜日）の夜に、モックと今回のフィードバックを照らし合わせて提案する流れが議事録にある。曜日は `node -e` で検証済み。

最短で示すべきもの:

1. つながる: 検索・投稿前確認・「置く」の言い換え方針。
2. 3ボタン: はなす主役化、手入力導線、押せないチップ削除の方針。
3. 横断: 記録がない期間をコミュニティが支えるサイクル図。

## 9. 受け入れ条件

- 初回ユーザーが、つながるで「近い声を探す」「投稿する前に見え方を確認する」まで迷わず進める。
- 3ボタンLINEで、初回ユーザーが「まずは記録すればよい」と理解できる。
- 押せない表示、意味が不明なチップ、画面変化が見えない操作が主要導線に残っていない。
- 次回10件以上のUXテストで、理解度と直感性が今回より改善している。
