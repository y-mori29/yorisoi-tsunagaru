# UI/UX仕様書

作成日: 2026-06-30
対象: よりそい つながる / よりそい 3ボタンLINE

## 1. UI/UXの基本方針

- 優しい雰囲気は強みとして残す。
- ただし、初回ユーザーには情緒的な言葉だけでなく、普通の操作名を併記する。
- 画面を開いた瞬間に「最初の1操作」が分かるようにする。
- 機能の豊富さではなく、迷わず使えることを優先する。
- 医療的な正解や症状改善を約束しない。

## 2. トンマナ

- 色: 現行の水彩・淡色・温かい印象は維持。薄すぎて読みにくい箇所はコントラストを上げる。
- 書体: 丸みのある日本語フォントは維持。ただし本文は読みやすさを優先する。
- 余白: 余白は残すが、情報が散らばって関係性が見えなくならないよう、グループ単位で近づける。
- イラスト/画像: 安心感の補助に使う。主操作の理解を邪魔する位置には置かない。
- 避けること: 押せそうで押せないラベル、飾りに見えるタグ、1画面に多すぎるCTA、未実装リンク。

## 3. ナビゲーション

### つながる

初回の中心は「読む/探す」。投稿は奥に置く。

```text
ホーム
  -> 近い声を探す
  -> 部屋を見る
  -> 投稿する前に表示を確認
  -> 投稿する / 自分だけに保存
```

### 3ボタンLINE

初回の中心は「はなす」。ふりかえる/みせるは、記録がたまると価値が出る導線として扱う。

```text
ホーム
  -> はなす
      -> 録音
      -> メモで残す
      -> AIと整理
  -> ふりかえる
  -> みせる
```

## 4. 画面仕様

### 4.1 つながる ホーム `/home`

目的:
登録前でも近い声を読める入口にする。

主な表示:
- 「近い声を探す」への明確なCTA。
- 体験談は、AI投稿風ではなく「体験談由来の声」と分かる位置づけ。
- 投稿CTAは強く出しすぎず、読んだ後に自然に置く。

改善:
- 「投稿する」は、初回では「声を投稿する」など分かる言葉を併記する。
- 体験談が当たり障りなく見える場合は、深さのある声カードを混ぜる。

### 4.2 つながる 探す `/find`

目的:
病気・症状・悩みから近い声にたどり着く。

主な表示:
- 検索欄。
- 選択中の病気/症状/悩み。
- 結果エリア。

改善:
- クリック後、選択状態がすぐ分かるようにする。
- 結果エリアへ自動スクロール、または上部に結果サマリーを出す。
- タグがクリック可能かどうかを明確にする。

空状態:
- 「専用部屋はまだありません」だけで終わらせない。
- 「近い症状・不安の声を読めます」へ誘導する。

### 4.3 つながる 投稿 `/post`

目的:
投稿不安を下げ、短文でも置けるようにする。

主な表示:
- 書く種類。
- 本文入力。
- 公開範囲。
- 投稿前プレビュー。

改善:
- 「置く」の横に「投稿する」「自分だけに保存」など普通の説明を出す。
- 投稿カードのプレビューを表示する。
- ハンドルネーム、病名、部屋名、公開範囲がどう見えるかを示す。

確認文言:
- 「この内容は、全体の近い声として表示されます」
- 「あとから自分のページで見直せます」
- 「病名を出したくない場合は非表示にできます」

### 4.4 つながる 部屋 `/rooms`, `/rooms/[id]`

目的:
深く近い声を読む場所にする。

改善:
- 「部屋に入る」は、何が変わるかを説明する。
- 「この部屋で吐き出す」は、初回では「この部屋に投稿する」と併記する。
- 部屋に入らなくても読める安心感を残す。

### 4.5 3ボタン ホーム `/`

目的:
初回ユーザーに「まず記録する」と分かってもらう。

主な表示:
- 主CTA: はなす。
- 補助CTA: ふりかえる、みせる。
- 最近の記録/空状態。

改善:
- `はなす` を一番強くする。
- 記録がない場合、ふりかえる/みせるは「記録後に使える」説明にする。
- `本人の記録` は押せそうなら削除または状態表示に変える。

### 4.6 3ボタン はなす `/simple/record.html`

目的:
診察や体調のことを、録音またはメモで残す。

改善:
- 録音を主役にしたまま、手入力を「録音できない時」の見える補助にする。
- 入力項目を最初から全部見せない。
- 「診療中にスマホを使ってよいか不安」への説明をヘルプに置く。

### 4.7 3ボタン ふりかえる `/simple/calendar.html`

目的:
自分の記録を読み返す。

改善:
- 記録カードを押すと詳細を読めることを明確にする。
- 日付、病院、診療科、要点の順で読む。
- 文字起こし全文は折りたたみでよい。

### 4.8 3ボタン みせる `/simple/show.html`

目的:
他の病院・診療科に見せやすくする。

改善:
- 「このまま見せるメモ」を主役にする。
- どの記録をもとにしているかを明記する。
- 情報量が多い場合は、見せる用メモ、記録選択、最近の記録の順に分ける。

## 5. 文言ルール

- 初回操作には普通の言葉を併記する。
  - 例: `声を置く（投稿する）`
  - 例: `自分だけに保存`
- 患者さんに責任を背負わせる言葉を避ける。
- 「症状が改善する」「治る糸口が見つかる」とは言わない。
- 価値は「近い声を読む」「整理する」「記録を残す」「あとで見返せる」と表現する。
