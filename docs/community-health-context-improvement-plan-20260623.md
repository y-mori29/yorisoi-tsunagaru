# よりそい つながる 病気・症状・不安の選択状態 改善計画

作成日: 2026-06-23
対象: `medicanvas/yorisoi-tsunagaru`

## 背景

直近の `/find` 改善で、病名検索、自由入力病名、診断前カード、近い部屋案内は入った。

ただし、これはまだ「探す」体験に寄っている。

コミュニティとしては、ユーザー自身が「自分はどういう病気・症状・不安を持っているのか」を選んだ状態にならないと、近い人とのつながりや、近い投稿の推薦が成り立ちにくい。

したがって、次の改善では、単に部屋を探すのではなく、自分の状態として病気・症状・不安を保存する仕組みに進める。

## 方針

病名・症状・不安は、部屋の有無に関係なく選べるようにする。

```text
病名を選ぶ
  ├─ 専用部屋がある
  │    └─ 自分の病気として保存し、専用部屋にも案内する
  └─ 専用部屋がない
       └─ 自分の病気として保存し、近い症状・不安の部屋へ案内する
```

つまり、部屋に入ることより前に、自分の状態を選べることが重要。

## 画面ごとの役割

### `/onboarding/condition`

最優先で作り直す画面。

役割:

- 登録直後に、自分の病気・症状・不安を選ぶ。
- 病名が確定していない人も入れる。
- 自由入力病名も保存する。
- 選んだ内容を、近い声・近い人・部屋推薦の土台にする。

推奨文言:

```text
あなたに近い声を届けるために、病気・症状・不安を選んでください。
病名がまだ決まっていなくても大丈夫です。
```

### `/find`

役割:

- 登録前は、読むための探索画面。
- 登録後は、探しながら自分の状態にも追加できる画面。

追加する導線:

```text
[自分の病気として選ぶ]
[この部屋を読む]
```

### `/me` または `/settings`

役割:

- 後から病気・症状・不安を変更できる場所。
- 公開範囲を選べる場所。

必要な項目:

- 主な病気
- ほかに気になる病気
- 症状
- 不安・暮らしの悩み
- 診断前・疑い・診断済み
- 公開範囲

### `/rooms`

役割:

- 選んだ病気・症状・不安に合わせて、近い部屋を出す。
- 病名部屋がない人にも、近い症状・不安の部屋を出す。

### `/post`

役割:

- 投稿に、自分の病気・症状・不安の文脈を紐づける。
- 毎回選ばせるのではなく、保存済みの状態から初期候補を出す。

## データ設計

詳細は `community-topic-data-design-20260623.md` の `MemberHealthContext` を正本とする。

中心になるデータ:

```text
MemberHealthContext
  ├─ primaryDisease
  ├─ secondaryDiseases
  ├─ symptoms
  ├─ concerns
  ├─ diagnosisStatus
  └─ visibility
```

## 実装順と進捗

### Step 1: 状態データを作る（実装済み）

- `MemberHealthContext` の型を作る。
- モック保存先を用意する。
- 自由入力病名も保存できるようにする。

実装メモ:

- `frontend/lib/onboarding/types.ts` に `MemberHealthContext`、`PatientTopicSelection`、症状・不安カタログ、選択作成ヘルパーを追加。
- 既存の `conditions` は互換用に残し、今後の正本は `healthContext` とする。
- 自由入力病名は `selectionMethod = free_text`、`templateKey = general` で受け止める。

### Step 2: `/onboarding/condition` を作り直す（実装済み）

- 病名検索を上部に置く。
- よく選ばれる病気を出す。
- 自由入力病名を `自分の病気として選ぶ` で保存できるようにする。
- 症状・不安も別カテゴリで選べるようにする。
- 診断前カードを独立して出す。

実装メモ:

- `/onboarding/condition` を「自分の病気・症状・不安を選ぶ画面」として再構成。
- `?disease=...`、`?diseaseName=...`、`?status=pending` のURLから初期選択できる。
- 「今は選ばずに進む」は残すが、選ばない状態と選択済み状態が混ざらないよう `healthContext` をクリアする。

### Step 3: `/find` を「探す + 自分に追加」にする（実装済み）

- 登録済みなら `自分の病気として選ぶ` を出す。
- 未登録なら、選択時に登録へつなぐ。
- 部屋がある場合も、ない場合も、まず病名を保存できるようにする。

実装メモ:

- 病名候補カードに `自分に追加` を追加し、オンボーディングの状態選択へつなぐ。
- 候補にない病名も `?diseaseName=...` で状態選択へ渡す。
- 診断前カードからも `?status=pending` で状態選択へ渡す。

### Step 4: `/me` または `/settings` に編集入口を作る（実装済み）

- `自分の病気・症状・不安` セクションを作る。
- 後から変更できるようにする。
- 公開範囲を選べるようにする。

実装メモ:

- オンボーディング状態を `localStorage` に保存・復元する共通層を追加。
- `/me` に `自分の病気・症状・不安` の要約カードを追加。
- `/settings` のアカウント内に編集入口を追加。
- 編集画面は既存の `/onboarding/condition` を再利用し、選択UIの分岐を増やさない。

### Step 5: 近い声・近い人・部屋推薦に反映する（実装中）

- 同じ病名の人。
- 同じ症状の人。
- 同じ不安の人。
- 病名は違うが症状や不安が近い人。
- 診断前・検査待ちの人。

を出し分ける。

実装メモ:

- `healthContext` から近いトピック名・部屋ID・投稿きっかけを作る共通ユーティリティを追加。
- `/home` の「近い声」タブで、選択済みの病気・症状・不安に近い投稿を優先表示する。
- `/rooms` の先頭に `あなたに近い入口` を追加し、選択済み内容から近い部屋を先に並べる。
- `/post` の気持ちチップと部屋候補を、保存済みの病気・症状・不安から並び替える。
- 未設定の場合は従来の固定おすすめに戻す。

## UI上の注意

- 「所属する」「マッチングする」という強い言葉は最初から出しすぎない。
- ただし、選んだ内容が近い声や近い人につながることは説明する。
- 病名がない人、病名を言い切れない人に圧をかけない。
- 部屋がない病気の人にも、自分の病気として選べた安心感を出す。
- 病名・症状・不安の公開範囲は、後から変えられるようにする。

## 次の実装対象

次に触るべき画面は、投稿完了後の反映と部屋詳細。

理由:

- 近い声・近い部屋・投稿候補の入口はできた。
- 次は、投稿した内容がどの文脈に紐づいたかを完了後にも見せる。
- 部屋詳細では、その部屋が「病名」「症状」「不安」のどれに近いのかを分かりやすく出す。
- その後、体験談データ由来の投稿更新ロジックへ接続する。

関連する残り画面の改築方針は `community-remaining-screen-restructure-plan-20260624.md` を参照。
