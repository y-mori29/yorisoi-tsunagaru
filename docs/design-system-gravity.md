# GRAVITY デザインシステム言語化

作成日: 2026-05-16
位置づけ: 「よりそい つながる」モック制作の **設計図** にするため、GRAVITYのデザイン要素を要素分解する。
参照元: `docs/gravity-research.md` の知見＋冨澤さん5/16 MTGでの実機観察＋公開情報。

---

## 0. なぜ「言語化」するか

GRAVITYを真似るとき、UIの形を真似ても効かない。
**「なぜそれが優しく見えるのか」「なぜハードルが低く感じるのか」**を、配色・形・モーション・コピーのレベルまで分解しないと、医療版に翻訳できない。

このドキュメントは「真似るべき要素を、再現可能な粒度まで分解した辞書」。

---

## 1. 全体世界観（World）

### 1-1. メタファー
- **宇宙・夜空・星**
- 機能名がすべて宇宙語彙で揃う：
  - フォロー → **心友**
  - 投稿 → **星**（つぶやき／流れ星／質問）
  - ホーム → **宇宙**
  - 探索 → **みつける**／**宇宙探索**
  - レコメンド → **星の予報**
  - DM → **心友トーク**
  - グループ → **惑星（プラネット）**
  - 性格診断マッチ → **心友ノック**
  - ランダム音声 → **宇宙通話**
- **なぜ効くか**：
  - 宇宙は誰のものでもないので「他人の領土に入る恐怖」が消える
  - 星=遠くにある=干渉されない、しかし瞬きで気づける、という距離感
  - 「フォロー」のような他SNS的な用語を排除しているので、SNS疲れの記憶を呼び起こさない

### 1-2. 配色トーン
- ベース：**深い夜空ネイビー**（#0E1336 〜 #1B2557）
- グラデ：**紫 → 青 → ピンク**（北極星のオーロラのような）
- アクセント：**白 / 薄水色 / 淡いピンク**（星のきらめき）
- **黒は使わない**（圧迫感）／**ピュア白も使わない**（コントラスト過剰）
- すべて発光しているような **soft glow**（CSS box-shadow を多用）

### 1-3. 質感
- グラデーション多用（ベタ塗りなし）
- 光の粒・パーティクル・うっすらした星のドット
- カードや投稿は **半透明 + ブラー**（ガラス調・glassmorphism）
- 角は **大きめの丸**（16〜24px radius）

---

## 2. タイポグラフィ

### 2-1. フォント
- 日本語：**ヒラギノ角ゴ Pro** / **Noto Sans JP** Regular
- 数字・英字：**Inter** / **SF Pro**
- 太字（Bold）は最小限。多用すると圧が出る
- **明朝体は使わない**（文学的すぎる）

### 2-2. サイズと階層
- 見出し：20〜24px（W500）
- 本文：15〜16px（W400・行間 1.7）
- キャプション：12〜13px（W400・グレー）
- 投稿のテキストは **読みやすさ優先**：16px・行間 1.75・1行あたり 22〜28文字

### 2-3. コピーのトーン
- **やわらかい・断定しない・温度のある**
- 例：
  - ❌「投稿しました」→ ⭕「星を流しました」
  - ❌「エラーが発生しました」→ ⭕「うまく届かなかったみたい。もう一度試してみて」
  - ❌「フォローしますか？」→ ⭕「心友になりますか？」
- 命令形を避け、提案形を使う

## 3. アバター・キャラクター

### 3-1. アバターの仕様
- **実写・自撮りは絶対NG**（運営側で防御）
- 運営提供のイラストアバターから選択
- アバターは **中性的な宇宙人風**（性別・年齢を匂わせない）
- 円形クロップ・周りに soft glow（星っぽさ）
- サイズ：48px / 64px / 96px / 128px

### 3-2. アバター装飾（ガチャ的）
- ヘイロー（後光）・宇宙ヘルメット・小惑星のペットなど
- レアリティが存在（コモン → エピック）
- 課金 or デイリーログインで星粒を貯めて交換
- 装飾は **アバターの周囲** にレイヤーとして重なる
- **なぜ効くか**：顔写真ではなく装飾で自己表現させることで、見た目バトル・盛り写真バトルが起きない

### 3-3. 公式キャラクター
- 「ぽんぽん（poompoom）」相当のマスコットがいる
- 中性的・柔らかい・宇宙的
- オンボーディング・空状態・通知音などの **感情の代弁者** として登場

## 4. 画面構成・レイアウト

### 4-1. グリッド
- モバイルファースト・縦長前提（横は使わない）
- マージン：左右 16〜20px
- 縦の余白は **狭くしない**（投稿カード間 12〜16px）
- セーフエリア（ノッチ・ホームインジケータ）を尊重

### 4-2. 主要画面構成
| # | 画面 | 役割 |
|---|---|---|
| 1 | **オンボーディング** | ハンドル名・性別・年代だけで3ステップ完了 |
| 2 | **タイムライン（宇宙）** | おすすめ／心友 切替 |
| 3 | **投稿（星を流す）** | テキスト・画像・公開範囲切替 |
| 4 | **流れ星受信（星と交信）** | 何もしてないのに知らない誰かから星が届く |
| 5 | **心友ノック** | 性格診断マッチで「考え方の近い人」と繋がる |
| 6 | **みつける（探索）** | ランダム他ユーザーページ訪問 |
| 7 | **プラネット（コミュニティ）** | 趣味別の集まり |
| 8 | **プロフィール** | 性格診断結果・アバター装飾・投稿履歴 |
| 9 | **通知** | 反応・心友・流れ星のお知らせ |
| 10 | **設定** | 通知・プライバシー・公開範囲のデフォルト |

### 4-3. ボトムタブ
- 5タブ：宇宙（ホーム）／みつける／**+ 流す**（中央・特別）／通知／プロフィール
- 中央の「+ 流す」は **特別ボタン**（フローティング感・グラデーション・タップで投稿モーダル）

---

## 5. コンポーネント

### 5-1. ボタン
- **プライマリ**：紫グラデ（#7C5BFF → #5B8BFF）・白文字・角丸20px・shadow有
- **セカンダリ**：半透明 + ブラー・白文字・角丸20px
- **ゴースト**：枠線のみ・透明背景
- 押下時：軽く膨らんで戻る（scale 0.97 → 1.0）
- **疲れる赤・警告色は最小限**

### 5-2. カード（投稿カード）
- 背景：半透明ダーク（rgba(255,255,255,0.05) + blur）
- 角丸：20px
- パディング：16〜20px
- アバター（左上）＋ハンドル＋経過時間（右上）＋本文＋画像＋リアクション行
- リアクション：5種スタンプ・各カウントは **小さく表示**（圧をかけない）
- コメント数：吹き出しアイコン＋数字
- **「いいね数で順位がつく」感覚は徹底排除**

### 5-3. 入力フィールド
- 背景：半透明・blur
- フォーカス時：紫グラデの薄い枠が浮かぶ
- プレースホルダー：やわらかいコピー（例「いまの気持ち、星にして流してみる？」）
- 文字数カウンタ：右下に小さく

### 5-4. モーダル・シート
- 下から **bottom sheet** でせり上がる（モバイル的）
- 上部に小さな drag handle
- 背景は半透明黒で奥がぼやける
- 閉じる動作は「下にスワイプ」も受け付ける

### 5-5. 通知バナー
- 上から **ふわっと** 降りてくる（フェード＋スライド・280ms ease-out）
- 自動消滅 4秒・タップで遷移
- 「流れ星が届いたよ」みたいな **柔らかい言い回し**

---

## 6. モーション・アニメーション

### 6-1. 原則
- **直線運動を避ける**（cubic-bezier(0.34, 1.56, 0.64, 1) などの spring 系）
- 220〜320ms 程度の **ほどよくゆっくり**
- 過剰なアニメは避ける（疲れる）
- **常に何かが微動している**（呼吸する光・粒の浮遊）

### 6-2. 具体例
- 投稿成功 → アバターから星が空に流れる短いアニメ
- 流れ星到着 → 画面上を斜めに光が走り、通知バナー降りる
- いいね → アバター周囲のglowが一瞬強く脈打つ
- ローディング → 星がゆっくり明滅
- 画面遷移 → フェード＋微スライド（突然変わらない）

## 7. 心理的安全性を生む仕様（コア）

### 7-1. 数値の見せ方
- **フォロワー数・いいね数を他人から見えなくする**
- 自分の投稿の総いいね数は見えない（来たいいねだけ通知で気づく）
- フォロー数も非公開
- → **「数を増やすゲーム」が成立しない**

### 7-2. 拡散の遮断
- **リポスト機能を作らない**
- → ある投稿が爆発的に広がる事故が構造的に発生しない

### 7-3. 公開範囲の細分化
- 投稿ごとに **3段階で公開範囲を選べる**：
  - 全体（おすすめに流れる）
  - 心友（相互フォローのみ）
  - 友達（指名した数人のみ）
- デフォルト設定をユーザーが選べる（迷ったら友達からスタート可）

### 7-4. 検索回避
- ユーザー検索を「拒否する」設定が可能
- → リアル知人にバレない

### 7-5. AI事前モデレーション
- 投稿は **公開前にAIチェック**（性的・誹謗中傷・詐欺・自殺示唆）
- 引っかかったらユーザーには「確認中」表示、運営に回る
- 月次セキュリティレポート公開（**透明性の演出**）

### 7-6. 通報・ブロック
- 投稿・コメント・プロフィール・チャットの **どこからでも通報** 可能
- ブロックはワンタップ
- ブロックすると相手にバレずに完全遮断

### 7-7. 自殺示唆等の検知
- キーワード検知時、投稿者本人に **静かに** 連絡先カードを通知
- 押し付けず、ただ「ここに窓口があるよ」と知らせる

## 8. つながりのハードルを下げる仕様（コア）

### 8-1. オンボーディング最速化
- **3ステップで完了**：
  1. ハンドル名（仮ニックネーム可）
  2. 性別・年代
  3. アイコン選択
- 性格診断は **後でやる**（強制しない）
- 登録メアド以外の個人情報は要求しない

### 8-2. 最初のワンアクション必須
- 登録完了直後に **「最初の星を流してみる？」** のモーダル
- 例文プレースホルダー：「はじめまして」「最近◯◯がつらい」
- スキップ可能だが、スキップしないとレコメンド精度が落ちる旨を伝える
- 投稿すると **即座に運営マスコットが反応**

### 8-3. 流れ星（受動的接触）
- **何もしてなくても誰かから星が届く**
- 24時間で消える（溜まらない・プレッシャーにならない）
- AI返信補助（返事のテンプレを提案）
- AI送信補助（自分から流れ星を送る時もAI下書き）
- → **「人と話すまでの心理的距離をゼロに近づける装置」**

### 8-4. 心友ノック（性格マッチング）
- 16性格診断（MBTI的）で「考え方の近い人」を提示
- **「趣味の一致」ではなく「考え方の癖の近さ」** で繋ぐ
- ノック送信 → 相手が承認 → 相互フォロー成立
- → 趣味マッチングよりも **会話が続きやすい** という構造

### 8-5. みつける（探索）
- ランダムに他ユーザーのページを訪問できる
- 「**出会い直し**」が常時発生する作り
- フォロー誰もいなくても**冷たいタイムラインにならない**

### 8-6. 質問箱（星と交信）
- お題が **1日1回降ってくる**
- 答えると関心持った人が拾う
- → **自分から知人に絡みに行く必要がない**

### 8-7. 通知設計
- 反応が来たら通知（喜びを増やす）
- いいね押された人は通知されない（圧を減らす）
- 流れ星到着・心友ノック・コメントは通知
- 通知音・バイブも柔らかい（暴力的でない）

## 9. ビジュアル要素（実装可能粒度の指針）

### 9-1. 画像
- **キービジュアル**：オンボ最初の画面・LP・ストアスクショの背景
- **オンボ挿絵**：各ステップごとに1枚（マスコットが案内）
- **空状態イラスト**：投稿ゼロ／検索結果ゼロ／通知ゼロのときに表示
- **エラーイラスト**：通信エラー・404 をやさしい絵で
- **キャラクター差分**：マスコットが喜ぶ／驚く／読んでる／寝てる など 5〜6ポーズ

### 9-2. アイコン
- すべて **手描き感のあるアウトラインアイコン**（lineicons / lucide ベースに装飾追加）
- ベタアイコン（fill）は最小限
- 機能ごとに統一感（線幅・角の処理）

### 9-3. パターン・装飾
- 背景に **小さな星のドット**（CSS背景画像）
- カードの隅に **きらめき装飾**（特別な投稿・公式コメント）
- 区切り線は使わず **余白で区切る**

### 9-4. 「何もない場所がない」原則
- 画面のどこを切り取っても、**何らかのビジュアル要素** がある
- 空白＝寂しさ、を作らない（適度な余白とは別）
- ただし **情報密度は低く保つ**（疲れさせない）

## 10. 真似てはいけない部分（GRAVITYの問題点）

冨澤さん5/16 MTGでの観察＋過去リサーチから：

| 問題 | 観察内容 | 医療版での扱い |
|---|---|---|
| 怪しいマッチング誘導 | 「リピート買いしてるシャンプーある」等のスパム流れ星が新規アカに5件届いた | **患者会オンボ経由で参入を絞る**ことで信頼担保 |
| 出会い目的の悪用 | 一部コミュニティが怪しい出会い系の温床 | **疾患特化ルームに限定**・1on1音声は実装しない |
| AIスパム返信 | AIが作った薄いコメントが大量に来る | **AI補助はあっても「下書き」までで強制送信させない** |
| ステマ騒動 | リリース時に過去にステマ疑惑あり | 我々は **患者会・医療者と一緒に公明正大に立ち上げる** |

## 11. このドキュメントの使い方（次ステップ）

1. このドキュメントの **各章** を「よりそい つながる」用に **翻訳** する
   → `docs/design-system-tsunagaru.md` で対応
2. 翻訳結果を元に **静的HTMLモック** を作る
   → `mockups/` 配下
3. 必要な画像（キャラクター・キービジュアル・アイコン）を **CodexCLI** で生成
   → `prompts/` に追加し、生成結果を `assets/images/` に配置
4. モックを月曜（5/18）20時 MTG で冨澤さんに見せる

## 12. 参考要素マトリクス（医療翻訳前のリスト）

| GRAVITY要素 | 医療翻訳の難易度 | 翻訳後の方針メモ |
|---|---|---|
| 宇宙メタファー | 高 | **自然・植物・木漏れ日** メタファーへ転換 |
| 心友（フォロー言い換え） | 中 | 「**そばにいる人**」「**並走者**」候補 |
| 流れ星（質問箱） | 低 | 「**今日のひとこと**」「**そっと届く声**」候補 |
| 心友ノック（マッチング） | 中 | 「**似たひとを探す**」程度のシンプルな言い回し |
| プラネット（趣味コミュニティ） | 低 | **疾患別ルーム**「UCのおうち」「クローンのおうち」など |
| 宇宙通話（音声） | 高（リスク） | **初期実装しない**。患者会オフィシャル開催のみ |
| アバター装飾ガチャ | 中 | 課金しないモデルなら **デイリーログイン報酬** 等で代替 |
| 投稿の3段階公開範囲 | 低 | そのまま採用 |
| 数値非表示 | 低 | そのまま採用 |
| リポスト不在 | 低 | そのまま採用 |
| AI事前モデレーション | 中 | **医療デマ検知** を追加 |
| 自殺示唆検知 | 高 | 患者特化なので **より精度高く** 実装 |
