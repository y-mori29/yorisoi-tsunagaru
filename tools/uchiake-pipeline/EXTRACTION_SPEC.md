# うちあけ体験談 抽出仕様（サブエージェント用）

入力: `data/chunk-N.jsonl`（1行1件のJSON）。各件は次のフィールドを持つ:
`id, workerId, approvedAt, title, q1_overview, q2_complaint, q3_course, q4_treatment, q5_issue, genre, age, gender`

出力: `data/composer-extracted-N.jsonl`。**入力と同じ順序・同じ件数**で、1行につき次の形のJSONを書く:

```json
{"id":"uchiake-0005","extracted":{"diseases":["うつ病","パニック障害"],"primaryDisease":"うつ病","symptoms":["自傷行為","イライラ"],"topics":["家族・パートナー","通院・治療"],"voice":"原文からの抜き出し1〜3文","voiceSource":"q5","safety":{"personalInfo":false,"aggressive":false,"medicalMisinfo":false,"note":""},"quality":"good"}}
```

## 各フィールドのルール

1. **diseases**: 本文中に出てくる病名・診断名を正式名称に正規化した配列（例:「UC」→「潰瘍性大腸炎」）。診断名が明記されていなければ空配列 `[]`。
2. **primaryDisease**: 中心となる病名1つ（文字列）。診断名がなく症状のみなら `null`。
3. **symptoms**: 本文に出てくる症状。短い名詞句（例:「手の震え」「下痢」「不眠」）。最大6個。
4. **topics**: 次のリストから該当するものすべて（この表記のまま使う）:
   仕事・学校 / 家族・パートナー / お金 / 通院・治療 / 薬との付き合い / 診断がつくまで / 眠り / 食事 / 外出・移動 / 見た目・周囲の目 / 気持ちのゆらぎ / 妊娠・出産 / その他
5. **voice**: フィードに流す「声」。q2（不満・不安）または q5（課題）を中心に、**原文から2〜6文を連続でそのまま抜き出す**。
   - 改変・要約・創作・言い換えは禁止。文頭の接続詞の削除と文末への句点追加のみ可。
   - **たっぷり取る。120〜300字程度が理想**（元の体験談の良さを削らない。短い原文ならそれ以下でもよい）。
   - **整えすぎない。** 言い回しの癖・くだけた表現・「…」「！」などもそのまま残す。生の声感が価値。
   - 内容がつながるなら、別の設問からの抜き出しを改行で1つだけ継ぎ足してよい（最大2ブロック。各ブロックは連続した原文であること）。
   - 生々しいネガティブ感情（不満・不安・苛立ち）はむしろ歓迎。選ぶ基準は「同じ立場の人が読んで『わかる』と感じるか」。
6. **voiceSource**: voice の主となる設問。"q1"〜"q5" のいずれか（2ブロック使った場合は主ブロックの設問）。
7. **safety**: 除外判定フラグ。
   - personalInfo: 個人が特定できる情報（実名・勤務先名・細かい地名の組合せ等）を含む
   - aggressive: 特定個人・属性への攻撃的表現を含む
   - medicalMisinfo: 明らかに危険な医療デマを断定的に勧めている
   - **ネガティブな感情は除外理由にしない。**
   - note: フラグを立てた場合の理由（任意・短く）
8. **quality**: "good"=そのまま使える / "ok"=使えるが声の候補が弱い / "poor"=短すぎる・内容が薄い・体験談として成立していない

## 作業ルール

- 体験の中身を創作・改変しない。判断に迷ったら quality を下げるかフラグを立てる（本文は変えない）。
- 出力はJSONLのみ。コメント・説明文・コードフェンスを出力ファイルに入れない。
- 全件処理後、`node src/validate.mjs N` を実行して PASS することを確認する（FAILなら該当行を修正して再実行）。
